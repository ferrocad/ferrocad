## P0 — keep the shipped grid path honest

These are defects or duplications in what we just shipped.

- [x] **Grid toggle ignores the drawn provider.** With the Coin (WGSL) provider
      active, `App_ToggleGrid` moved only the native flag, so the shader grid kept
      drawing and the command looked dead. Fixed 2026-10-22: `FerroCAD.Grid.enabled`
      is the single switch, `App_ToggleGrid` writes it, the registry has a `refresh`
      callback, and the Coin provider reads the shared switch. Breakdown:
      [`tasks/grid-visibility.md`](tasks/grid-visibility.md); user page
      [`user/how-to/grid-visibility.md`](user/how-to/grid-visibility.md).
- [x] **Provider rename.** `semantic` → `ferrocad` (label `FerroCAD (native)`)
      landed; the external `ferrocad-grid-overlay` repo declares its own id, so it
      is unaffected.
- [x] **Residual black frames.** Fixed 2026-10-22 by replacing the hand-rolled
      dma-buf ring and its "reuse after N submissions" distance rule with
      `gpui_interop 0.1.3`'s `WgpuSharedBufferRing`, the upstream fix for
      `bite-gpui/gpui_interop#1`. It presents only a frame whose acquire fence has
      already signalled (fence stripped), recycles a slot on the consumer's release
      with a 250 ms fallback, drops frames overtaken by a newer one, and repeats the
      last good frame when nothing is ready. Pinned to `bite-gpui`/`bite-gp-wgpu`
      `=1.24.401` and wgpu 29: the 1.25 line uses wgpu 30, which would split the
      device from `ferrocad_wgpu` (wgpu 29). Still needs a live run: an X11/Wayland
      session with the Coin grid at 4x MSAA (the intermittent race cannot be
      reproduced headless).
- [x] **External-mod ingestion.** Decided 2026-10-22: **both stay** during the
      transition. `mods/GridOverlayCoin` is the maintained copy (it carries the S4
      settings aliasing and the `coin` backend id the shell and tests use);
      `ferrocad/ferrocad-grid-overlay` is the standalone distribution, pinned at
      `3b376cb`, and currently lags it (older id, no settings aliasing). Deleting the
      in-tree copy would break offline builds, the test suites and the seeded
      provider list, so nothing is fetched at build time. Provenance and the sync
      recipe live in `mods/GridOverlayCoin/README.md`.
- [x] **One home for the WGSL.** The canonical copy is
      `mods/GridOverlayCoin/Resources/grid_overlay.wgsl`. `ferrocad_wgpu` carries no
      duplicate: its naga and pixel tests read the mod's file from the workspace tree
      (the same way the gizmo-skin tests read `mods/GizmoOverlayShader/`) and **skip
      those checks when `mods/` is absent**, so an unpacked crate still tests. The
      standalone repo mirrors the same file. Decided 2026-10-22: the shader is the
      mod's worked example, and a test-only loader can cross the tree while a
      published `include_str!` cannot.
- [x] **Provider UX.** The inactive provider's command no longer looks runnable:
      `provider_features()` carries each backend's `command`, and the Dev Tools
      command list dims and disables the losing backend's entry (with an
      "Inactive: another <feature> provider is selected" tooltip) while the active
      one keeps its click. Landed 2026-10-22; see
      [`workbenches/mod-providers.md`](workbenches/mod-providers.md) §Notes and
      limits. The registry remains advisory — a mod that ignores `activeProvider`
      can still draw, and the filter does not gate execution.
- [x] **Provider persistence.** `ParamGet` is file-backed (P0.7/S3), so the selected
      backend and every advertised setting survive a restart. The headless default
      stays in memory; the shell enables the config file when `GuiUp` is set.
- [x] **Per-document deactivation.** The GUI now has a deactivation slot: the App
      facade (`FreeCAD.newDocument` / `open` / `closeDocument` / `setActiveDocument`)
      fires `FerroCADGui`'s `addDocumentListener` slot — created / activated /
      deactivated / closed — before the document disappears, and the provider
      registry subscribes to it, so a closing document's attachment (the Coin grid)

      upstream-shaped `addDocumentObserver` forwards to the same slot. Landed
      2026-10-22; `tests/test_gui_document_observers.py` (11 tests) covers ordering,

      [`workbenches/mod-providers.md`](workbenches/mod-providers.md) §The document

## P0.5 — UI reset: move the dev tooling out of the main window

Full breakdown: [`tasks/dev-tools-window.md`](tasks/dev-tools-window.md).

The main window becomes the viewport plus a minimal status line. The command surface
(the tooling menu; a flat bar when P0.5 landed, the vertical list since P0.6/T6), the
inspector, the property editor and the console move to a separate **Dev Tools** window,
GIMP-toolbox style, toggled with `Ctrl+Shift+D` and reached from the title-bar `☰` app
menu (its first entry). This is a clean slate for the future navigation/tool design,
not a redesign; commands, selection and the Python API are unchanged. Dialogs stay
over the viewport; the transient tool strip stays in the main window until the new
interaction model replaces it.

- [x] Extract the four panels into reusable views, add `DevTools`, slim
      `Shell::render`, add the toggle/lifecycle, and cover it headlessly. Landed
      2026-10-22: `dev_tools.rs` (second window over `Entity<Shell>`, no viewport),
      `Dev_ToggleTools` (`Ctrl+Shift+D`), dialogs stay in the main window. D6 is done:
      `actions-and-tools.md`, `app-shell-vision.md` §5 and this backlog carry the
      reset.
- [x] **GPU adapter selector (dev-only).** Dev Tools has a GPU panel between
      Providers and Commands: `Auto` plus every enumerated adapter, the persisted
      row accented. The choice is stored at
      `User parameter:BaseApp/Preferences/View/GpuAdapter` (`auto`,
      `backend:vulkan|gl|metal|dx12`, `adapter:<name>`), and selecting a row
      recreates the viewport. It applies to the **image path** only: zero-copy
      presentation still builds its renderer on the window adapter, which the
      panel and status line state explicitly. Breakdown:
      [`tasks/dev-tools-window.md`](tasks/dev-tools-window.md).
