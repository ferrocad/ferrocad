## P0 — keep the shipped grid path honest

These are defects or duplications in what we just shipped.

- [ ] **Residual black frames.** Intermittent, **only with the WGSL/Coin grid**; the
      native grid does not reproduce them. The 3-slot ring reduces but does not
      eliminate them. Capture one with `FERROCAD_TRACE=1` (look for
      `frame N: black`, `presenter slot=`, `reuse_distance`, `via_release`) and attach
      it to `bite-gpui/gpui_interop#1`. When upstream answers with a consumer-completion
      signal or a fence recipe, replace the conservative distance rule.
- [ ] **External-mod ingestion.** Decide whether `ferrocad/ferrocad-grid-overlay`
      becomes the single Coin backend (delete `mods/GridOverlayCoin`) or both stay
      during a transition. If the former, fetch it with `cargo xtask mods` (or a
      pinned tag) and make the duplicate `GridOverlayCoin` a thin compatibility shim or
      remove it.
- [ ] **One home for the WGSL.** It currently lives in
      `crates/ferrocad_wgpu/shaders/`, `mods/GridOverlayCoin/Resources/`, and the
      external repo. The external repo should own it; the crate copy is the reference
      used by the naga test. Either vendor the crate copy from the repo or make the
      test read the mod file.
- [ ] **Provider UX.** The inactive provider's command still appears in the command
      list and the actions bar; hide or disable it by `activeProvider` (a shell-side
      filter). The registry is advisory — a mod that ignores it can still draw; keep
      documenting that.
- [ ] **Provider persistence.** `ParamGet` is in-memory, so the selected backend does
      not survive a restart. This waits on the parameter backend, not on the provider
      API.
- [ ] **Per-document deactivation.** Registration/deactivation is handled on the next
      activation because `FreeCADGui` has no document-deactivate slot. Add one if a mod
      needs to react to a document closing.

## P0.5 — UI reset: move the dev tooling out of the main window

Full breakdown: [`tasks/dev-tools-window.md`](tasks/dev-tools-window.md).

The main window becomes the viewport plus a minimal status line. The actions bar
(the tooling menu), the inspector, the property editor and the console move to a
separate **Dev Tools** window, GIMP-toolbox style, toggled with `Ctrl+Shift+D`. This
is a clean slate for the future navigation/tool design, not a redesign; commands,
selection and the Python API are unchanged. Dialogs stay over the viewport; the
transient tool strip stays in the main window until the new interaction model
replaces it.
