### 0.1 What the last round changed — and what it did not

At the start of the 2026-10-23 backlog the Part suite was **2 passed, 1 failed, 89
errored, 4 files failed to load**: Part existed as a crate but not as a usable
workbench. It is now a loaded, complete surface — every upstream module imports,
every API its tests touch exists, and **all 531 runnable cases pass**. The work
split into three kinds:

- **Surface breadth (the bulk of the lines):** constructors and overloads, conics and
  NURBS conversion, `ShapeFix`/`ChFi2d`, `Sketcher::SketchObject`, the `RuledSurface`/
  `Extrusion`/`Mirroring`/`Body` objects, and torus/wedge/revolution/helix/thread/tube.
- **Semantics (the hard part):** the lineage layer (persistence in both formats and the
  exact 20/47 reverse maps), a live `Shape.Placement`, upstream's cyclic-expression
  wording, and the edge-curve basis rule.
- **Harness honesty:** a narrow `Draft` shim removed the two load errors without
  shadowing upstream's Draft in the `--draft` group.

The architectural claim was tested and held: **topological naming is a lineage layer,
not a kernel concern.** `ferrocad_lineage` (payload-generic vocabulary and policy) +
`ferrocad_part` (storage and resolution) + the Python frontends is the shape that made
the 20/47 result possible, and it never required OCCT to know what a document is.

What this round did **not** do:

- Four consumer shapes (`makeShell`, `makeSolid`, `makeLoft`, `makeFilledFace`) still
  store an empty lineage, and two guarded counts (`FaceMakerCheese` 10,
  `makeShellFromWires` 24) are composed aliases rather than element counts. Those six
  asserts still skip.
- It did not build the **Python feature-proxy** layer, which is the gate to Draft M2
  and SimpleCAD.
- A few documented approximations remain: `Part.makeHelix` still uses the interpolating
  B-spline, `makeThread` is a circular-profile pipe, and `makeTube` refuses B-spline
  spines. The kernel-side exact versions exist.

Everything below follows from that list.
