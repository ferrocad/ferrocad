## P5 — polish and follow-ups (carried)

- [ ] **`opencascade-sys` on Windows/MSVC.** Tracked as
      [ferrocad#1](https://github.com/ferrocad/ferrocad/issues/1); upstream the
      defect is already [bschwind/opencascade-rs#234](https://github.com/bschwind/opencascade-rs/pull/234)
      (open, mergeable; superset of our vendored patch — it also wraps the cxx
      pointer bindings and links `advapi32`). Port #234 onto
      `third_party/opencascade-sys` rather than extending our own edits. Two
      MSVC-only failures, both from OCCT's `DEFINE_STANDARD_HANDLE`: on MSVC it
      makes `Handle_T` a *derived class* (for C++/CLI) and `Handle(C)` stays
      `opencascade::handle<C>`, so the two are distinct types; on GCC/Clang they
      are the same.
      1. **Fixed here.** `opencascade-sys` allocated `new opencascade::handle<T>`
         for a `unique_ptr<Handle_T>` (C2440); `third_party/opencascade-sys`
         patches the 17 sites to `new Handle_T(…)`. Our own
         `crates/ferrocad_occt/include/fc_curve.hxx` had the same pattern once
         (`new Handle(Geom_Curve)`) and is fixed in place.
      2. **Open.** cxx's `#[Self = "Type"]` shims take the address of the member
         first (`void (*f)(const TopoDS_Face&, const Handle_Poly_Triangulation&) =
         &::BRepLib_ToolTriangulatedShape::ComputeNormals;`), which only resolves
         when the bridge's `Handle_T` *is* OCCT's `Handle(T)`. On MSVC it is not,
         so every `#[Self]` binding whose signature mentions a handle fails
         (`C2440: cannot convert from 'overloaded-function'`).
         Candidate fixes, in order: (a) force OCCT's compatibility typedef in the
         bridge translation units — a compat header included before any OCCT
         header that `#undef`s `DEFINE_STANDARD_HANDLECLASS` and re-defines it as
         `typedef opencascade::handle<C1> Handle_##C1;` (this also makes the 17
         header edits above unnecessary); (b) bridge the affected functions
         through free wrapper functions instead of `#[Self]`; (c) upstream report
         to `opencascade-rs`.
      Measure: `gh workflow run edition-windows.yml` (OCCT fetch + kernel build +
      `bundle --edition parametric --occt --check-init` + zip smoke test; ~10 min
      per attempt). When green, restore the `windows-latest` entry to the
      `edition` matrix in `release.yml` and delete the dispatch workflow.
- [ ] **macOS re-enable.** The upstream blocker is diagnosed (a dead `cocoa` import

      updated for `lib/` and editions, CI legs — is unbuilt. See
      [`architecture/macos.md`](architecture/macos.md).
- [ ] **Publish the book.** `python3 tools/build_book.py --build` renders the Diátaxis
      edition into `target/user-book/book`. The separate
