### 0.1 What the tree already has

- **The OCCT boundary is Rust.** `ferrocad_part_cxx` is gone; `ShapeFix`, `ChFi2d`,

  not our seam.
- **One document, four runtimes.** `RustAppBackend` is the document half of every desktop
  and browser configuration; `PythonScriptHost`, `PywasmScriptHost`, `JsScriptHost` and
  `runtime=plain` are the script halves. `ferrocad_shell_web` switches them in the
  browser; the desktop switches with `--script-host=`.
- **The browser shell is real.** M0–M6: the shell runs in Chrome, draws a `Part::Box` +
  `Part::Fillet` document on the wasm kernel, edits it, opens/saves `.FCStd`, and passes a
  headless smoke check.
- **Mods are a delivery format.** Packs carry entry scripts and the `Resources/` they read;
  wasm addons use the `ferrocad_addon` ABI; the browser and desktop compose the same
  ordered host chain.
- **The interaction work landed.** Transform A1–A3 and U1–U6: one `TransformSession`, the
  Move pill, the 3-D tape, loadout slots, `Select ▾`, hover-to-arm, and the locked pending
  context.
- **The manipulators are editors.** Push/Pull and Fillet share one pending-edit writer, a
  docked numeric row, a stem that rides the swept ghost, a hard range whose ceiling the
  kernel measures by bisection, and re-opening: picking the cap of an extrusion or the
  round (face or boundary edge) of a fillet seeds the handle and edits that feature in one
  transaction. A feature the kernel refuses is rolled back, and a refused commit re-arms
  the handle. See §20 of
  [`../developer/interaction/gizmo-manipulators.md`](../developer/interaction/gizmo-manipulators.md).
- **The Part containers are upstream-shaped.** `Refine` is read (default on, unified by the
  kernel and re-named through a measured history), `MultiCommon.Behavior` exists, a lone
  compound argument is flattened, and the four `Part_Fuse`/`Cut`/`Common`/`Compound`
  commands create one undoable object over the selection.
- **The sub-shape seam is one build.** `Shape.generalFuse` answers every input from one
  boolean, a replaced vertex reports its image, `Edge.Orientation` and an edge's
  `Placement` reach the shapes that consume it, a wire wrapped from a shape counts its

  `Part.Circle`'s analytic frame reaches its edge's parameter 0, and the three shape
  booleans honour upstream's signed `tolerance`. See
  [`../developer/workbenches/part-shape-edits.md`](../developer/workbenches/part-shape-edits.md).

## P4 — Constraints and sketches, with a bound solver

**Scope decision unchanged: FerroCAD owns everything around the solver and does not write
one by default.** The constraint model, storage, selectors, diagnostics and UX are ours;
the numerical solve comes from PlanGCS (2D) or OndselSolver (3D).

### 4.1 State

- PlanGCS is vendored upstream, **not templated**, dependency-light (Eigen, one Boost
  graph header, FreeCAD stubs) and **verified bindable** in the 2026-10-30 fan-out.
- OndselSolver is still not checked out; it is unverified for sketch constraints.
- No constraint model, no `Constraints` property, no solver in the workspace.
- **SK1's prerequisite is still missing:** sketch geometry has no stable id, so a
  constraint cannot reference a curve across a recompute.

### 4.2 Slices

1. **SK1 — the geometry identity and the constraint model.** Add a document-scope geometry
   id (UUID + curve parameters) to each sketch entry, then typed constraints holding
   `(object, geometry id, PointPos)` + kind + params. *Acceptance:* round-trips through
   `.FCStd`, resolves after a reordering recompute, reports a dangling reference.
2. **SK2 — the solver adapter.** One trait over the chosen solver, with DOF analysis,
   redundant/conflicting detection and deterministic reporting mapped back to constraint
   ids. *Acceptance:* a triangle with three dimensions converges from a perturbed start;
   an over-constrained sketch returns the redundant set; results are identical across runs.
3. **SK3 — `Sketcher::SketchObject` becomes real.** Add `Constraints` and a solve result;
   add `python/Sketcher` (`addConstraint`, `delConstraint`, `setDatum`, `solve`,
   `getDatum`). *Acceptance:* an upstream-shaped script builds a constrained sketch and
   reads back its DOF count. This also unblocks P2's `make_sketch`.
4. **SK4 — draw on a workplane.** *(a)* close the loop in `PolylineTool`; *(b)* register the
   tool in the parametric edition and add a `create` provider that builds one
   `Part::Feature` inside one named transaction; *(c)* the acceptance test: four snapped
   clicks on a tilted plane, every vertex within f32 tolerance, one undo removes it. The
   ordering, snapping and routing are built; the creation half does not exist. Decide the
   two-creation-pipelines question and project tool points onto the active plane.
5. **SK5 — path to solid.** Extrude the committed wire through `Part::Extrusion` in one
   transaction; editing the path updates the extrusion.
6. **SK6 — constraints as refinement.** Select geometry, add a dimension, watch the profile
   and its extrusion update; an unconstrained drag still works.

Decisions still open: the state channel for "solved / failed / over-constrained"; whether an
attached sketch re-maps when its support's lineage changes; and whether OndselSolver is ever
needed for assembly. The 2D-crate and one-model decisions are settled (one kernel-free model
crate + one solver binding).

## Closed since the last backlog

The 2026-11-14 backlog closed with the P2 seam rounds. In order:

- **The shape booleans match upstream's signature.** `Shape.fuse`/`cut`/`common`/`multiFuse`
  take `(other, tolerance=0.0, *, noElementMap)`; the second positional argument is the
  fuzzy tolerance, not a house `glue` flag, so a script that passes one positionally now
  reaches the kernel. Both `test_union` geometry records pass.
- **`Shape.tessellate` meshes like FreeCAD.** The omitted `angular` is upstream's
  `defaultAngularDeflection`, `min(0.1, linear * 5 + 0.005)`, computed by one
  `ferrocad_geom` helper that the STL path shares; `test_mesh_glue` is **6/6**.
- **`Face.cutHoles` and `Part.Cylinder(circle)` exist.** `cutHoles(list)` is upstream's
  raw `BRepBuilderAPI_MakeFace::Add` per wire (no reversal, wire-shaped shapes only, null
  face raises `ValueError` first), and `Part.Cylinder` reads a circle base's frame.
  `test_mesh_surfaces` is **7/7**.
- **The `flatmesh` unfold no longer tears.** A fan-closing triangle used to *move* a vertex
  an earlier fan member had already laid, so the sheet was torn at every interior vertex
  and the tear compounded around a long strip: a finely meshed cone wall (6 120 triangles)
  measured 1 155 mm² against its 1 025 mm², while the coarse mesh was exact. A vertex is
  now laid once; the same mesh measures 1 025.16, and a 0.006-deflection cone test pins it.
- **The Part containers became upstream-shaped.** `Refine` is read and defaulted on, its
  lineage measured rather than assumed; `MultiCommon.Behavior`; single-compound
  flattening; `MultiFuse` arity; `Part.generalFuse(fuzzy)`; the four interactive boolean
  commands. Fidelity work: Part and SimpleCAD numbers did not move, which was the point.
- **The sub-shape seam became one build.** One boolean answers every `generalFuse` input,
  a replaced vertex reports its result image, `Edge.Orientation` and an edge's `Placement`
  reach the shapes that consume them, and `App::Part`/`PartDesign::Body` answer the
  geo-feature-group extension. It closed 20 SimpleCAD failures, including all eight
  `test_surface_line` failures, and both `test_rotate_edges` cases and both
  `test_elongating` cases followed in the same seam.
- **A wire wrapped from a shape counts its edges, and `Face.addWire` exists.** The empty
  analytic cache made `bool(obj.Shape)` false for a real wire, which skipped it in
  SimpleCAD's dangling-wire heal; the length and iteration now fall back to the B-Rep, and
  the offset path's `rem_f.addWire(...)` is implemented as upstream's
  `BRep_Builder::Add`.
- **A circle's frame reaches its edge.** `edge_from_circle` built `gp_Ax2` from the normal
  alone, so a `-Z` circle's edge seam sat at parameter π relative to the `XAxis` the circle
  reported; two rims that should coincide were sewn as two arcs (three circles instead of
  two in SimpleCAD's boss rebuild).
- **The shape booleans honour their tolerance.** `0` leaves the kernel alone, `> 0` is the
  fuzzy value, `AUTO_FUZZY` is the bounding-box diagonal × confusion, through one helper on
  `BRepAlgoAPI_Cut`; the document booleans pass `AUTO_FUZZY` because upstream's constructors
  compute it.
- **The `close_holes` experiment was reverted, not shipped.** The rule closed
  `test_edge_deletion`, but it edits the reference checkout; the probes attributed the two
  failures to SimpleCAD's documented cap policy, and `../simplecad` stays clean at
  `9180c4b`.
- **The `part_boot` shell-helper test stopped reading a hard-coded `Box`** and reads the
  displayed object's name from the stage instead, so `ferrocad_part_py` is green.
