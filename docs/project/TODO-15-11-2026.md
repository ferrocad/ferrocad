### 2.2 The `close_holes` finding (do not patch the checkout)

- **Recorded, not fixed.** On a box with a side face deleted, the boundary loop has four
  neighbours, so the one-neighbour fill never applies; the remaining coplanar guard is
  false and the function caps the loop by design. `Part.Face`/`makeSolid` return a valid
  closed body. `test_hole_closing.py` asserts the one-neighbour wall *does* close, so the
  two `test_edge_deletion` failures — and `test_rounding`'s erase-then-refuse sample, which
  expects the same opened body — are an **upstream expectation mismatch**, not a seam
  defect. `../simplecad` stays at `9180c4b`; the twelve-line experiment that closed them was
  reverted. If upstream changes the policy, revisit.

## P4 — Constraints and sketches, with a bound solver

**The scope decision changed at SK2 (2026-11-15): FerroCAD writes the 2-D solver.** The
original plan bound upstream's PlanGCS; a pure-Rust solver was chosen instead, because
PlanGCS would add an Eigen/Boost C++ closure to a Rust workspace, grow `target/` for a
small vocabulary, and is not in the sparse upstream checkout this repository measures
against. No contract gate required it, and the contract is behavioural, so a later PlanGCS
binding could replace the implementation behind the same API. OndselSolver (3D) is still
unbound and unverified; it is not needed for sketch constraints.

### 4.1 State

- **The constraint model exists (2026-11-15).** `Sketcher::SketchObject` stores typed
  records in a `ConstraintData` string list, `python/Sketcher` ships
  `Constraint`/`PointPos`/`GeoUndef`, and `addConstraint`/`delConstraint`/`setDatum`/
  `getDatum`/`solve`/`Constraints`/`RedundantConstraints`/`ConflictingConstraints` plus the
  four autoconstraint calls are installed on `ferrocad.DocumentObject`. Contract:
  [`../developer/workbenches/sketch-constraints.md`](../developer/workbenches/sketch-constraints.md).
- **SK1's identity landed the same day.** Each geometry element carries a stable id
  (`GeometryIds`) and a construction flag (`Construction`), index-aligned with `Geometry`;
  a constraint stores the id, so `delGeometry` drops only the constraints that named the
  removed element and the survivors re-index without being scrambled. `-1`/`-2` name the
  root axes (validation, `solve`, detection); external geometry (`-3` and below) is refused
  by name. Construction geometry is counted, constrainable and excluded from `Shape`.
- **SK2 landed: the solve is real.** `ferrocad_sketch_solver` (pure Rust, depends only on
  `ferrocad_curves`) parameterizes points, line segments, circles and arcs, builds analytic
  residuals for the whole kind list, iterates Levenberg-Marquardt, and reports DOF,
  redundancy and conflicts from a rank analysis. `solve()` writes the solved geometry back
  and returns the DOF count; `execute()` solves too, so a recompute keeps a sketch solved;
  a failed solve writes nothing.
- **The solver works per island, and has a drag seam.** A constraint couples only the
  geometry it names, so the sketch is split into connected components: an unconstrained
  island costs nothing, an already-satisfied one skips the iteration but keeps its rank
  analysis, and an active one solves and diagnoses on its own (which is what makes a
  two-conflict sketch diagnosable at all). `SoftPrior` + `solve_with_priors` add weighted
  drag rows that never enter the convergence test or the rank analysis, and
  `SketchObject.drag(geometry, pos, target)` is their Python consumer: it moves a point
  toward the pointer, loses to every hard constraint, and reports the same DOF as
  `solve()`.
- **What the solver does not do.** Ellipses and splines are stored but not moved (and
  cannot be constrained); a first-order method can stall on a degenerate start (a
  horizontal line given `Vertical` *and* a length), which reports `-1`; `Block` pins at the
  position the solve started from rather than a stored reference.
- **The 2-D → 3-D loop runs on both rails.** The parametric edition contributes the
  generic `polyline` tool under two ids: `Part_Polyline` builds a parametric wire
  (`Points`/`Closed`) plus the `Part::Extrusion` that links it, in one transaction;
  `Sketch_Polyline` builds a `Sketcher::SketchObject` instead, the extrusion linked to it
  the same way. Editing the points moves the pad either way. On the sketch rail the
  drawing is projected into its own plane and placed back with
  `Placement(origin, Rotation(x, y, z, "ZXY"))`, so a profile drawn on a face stays on
  that face and the autoconstraints read in the sketch's frame.
- **The dimension loop closes (2026-11-15).** `Sketch_Dimension` adds a *driving* datum to
  the selected sketch edge at the value it already has — `Radius` for a `Part::GeomCircle`,
  otherwise the endpoint `Distance` — which moves nothing, then `setDatum` resizes the
  profile and the linked pad follows on recompute. So the whole chain exists end to end:
  draw a profile → constrain it → dimension it → edit the datum → the solid changes.
  Measured: a closed four-point profile yields 10 constraints, `solve() == 2`,
  `RedundantConstraints == [6]`, and `setDatum(10, 20.0)` takes the pad's `YLength` from
  10 to 20 (`tests/sketch_pad_round_trip.rs`).
- **The vertex grips, and `drag` behind a manipulator (2026-11-15).** A selected sketch
  publishes one **declared plane handle** per topological vertex, so a vertex drags inside
  the sketch's own plane and the commit (`sketch_drag`/`drag`, `[u, v]`) runs
  `SketchObject.drag` in one transaction. `ferrocad_stage::DeclarativeKind` gained `Plane`
  (two coordinates, ray/plane drag, no numeric row) and the transport gained `kind:
  "plane"` + `value_v`. The same pass fixed the specs half of the declarative seam: the
  shell was handing the provider the selection's **name**, so a type-specific provider was
  silently inert; it now gets the document object, exactly like the interaction half and
  the probe.

### 4.2 Slices

1. **SK1 — the geometry identity and the constraint model.** *(Landed 2026-11-15: the
   typed records, the stable per-element ids, construction geometry and the root-axis
   references. `.FCStd` round trip pinned in `tests/test_sketch_constraints.py`.)* What the
   acceptance asks for and this does not yet cover is a **document-scope** id — unnecessary
   while a constraint is sketch-local — and external geometry (`-3` and below), which is
   what would need one. *Acceptance:* resolves after a reordering recompute (pinned),
   reports a dangling reference (pinned as `solve() == -1` and a `ValueError` from
   `Constraints`).
2. **SK2 — the solver.** *(Landed 2026-11-15 as a pure-Rust solver rather than a PlanGCS
   adapter.)* DOF analysis, redundant/conflicting detection and reporting mapped back to
   constraint indices; the residual rows are pinned per kind in the crate's unit tests.
   *Acceptance:* a rectangle converges from a perturbed start and reports four degrees of
   freedom; the redundant set is found from the Jacobian's rank; an over-constrained sketch
   is refused with the geometry untouched; results are deterministic (no randomness
   anywhere in the solver).
3. **SK3 — `Sketcher::SketchObject` becomes real.** *(Landed 2026-11-15: the constraint
   property, the Python surface, `python/Sketcher`, `Draft.make_sketch`/`draftify` green —
   `test_modification` **33/0/0/0**) — and the DOF count now comes back from `solve()`.*
4. **SK4 — draw on a workplane.** *(Landed 2026-11-15.)* The parametric edition registers
   the native `polyline` tool, and `Part_Polyline` starts it. Four snapped clicks on a
   tilted plane finish a creating commit; the edition's hook builds a parametric
   `Part::FeaturePython` wire from the collected points **and** its `Part::Extrusion`
   in one named transaction, so one undo removes both. Every vertex survives the tool
   to f32 precision. Acceptance:
   `crates/ferrocad_parametric/tests/polyline_round_trip.rs`.
5. **SK5 — path to solid.** *(Landed with SK4.)* The extrusion's `Base` is the wire and
   its `Dir` is the profile's own plane normal (computed from the first three
   non-collinear points, so a tilted profile extrudes perpendicular to itself).
   Editing the wire's `Points`/`Closed` rebuilds it on the next recompute and the
   extrusion follows; a profile the kernel refuses keeps the wire and drops only the
   pad. `Thickness` on the wire is the extrusion height.
6. **SK6 — constraints as refinement.** *(Landed 2026-11-15.)* The drag primitive came
   first: `SketchObject.drag(geometry, pos, target)` solves with a `SoftPrior`, keeps the
   DOF count and `RedundantConstraints` untouched, and refuses a root axis. The
   selection → dimension → profile → pad loop then closed with `Sketch_Polyline` (a
   constrained sketch instead of a bare wire, padded in the same transaction) and
   `Sketch_Dimension` (one driving datum at the edge's current value; `setDatum` resizes
   the profile and the pad follows). The **vertex grips** make it interactive: a declared
   plane handle per vertex, whose commit is the same `drag`. Acceptance:
   `crates/ferrocad_parametric/tests/sketch_pad_round_trip.rs` and
   `.../sketch_drag_round_trip.rs`; `Part_Polyline` and its `polyline` id are untouched,
   so the two creation paths never collide.

Decisions still open: the state channel for "solved / failed / over-constrained"; whether an
attached sketch re-maps when its support's lineage changes; and whether OndselSolver is ever
needed for assembly. The 2D-crate and one-model decisions are settled (one kernel-free model
crate + one solver binding).

## Closed since the last backlog

The 2026-11-14 backlog closed with the P2 seam rounds. In order:

- **A degenerate edge refuses a curve, and an elementary surface is writable.** `Edge.Curve`
  raises `TypeError` on a sphere pole or a cone apex instead of returning `None`, and
  `Part.Cylinder`'s `Radius`/`Center`/`Axis` are writable with a
  `toShape(u1, u2, v1, v2)` band, so a caller can fill a surface in and turn it into the
  face of a hole wall. It closed seven SimpleCAD failures: `test_healing` **14/14** and
  `test_degenerate_drawing` **5/5**.

  field of the document object, so `set_label` records a `Change::Label`: an operation that

  mirror lands in the same transaction and one undo restores both halves. It closed five
  SimpleCAD failures — `test_union` is **16/16** and both `test_rotation` document tests
  pass — and the contract is
  [`../developer/architecture/transactions.md`](../developer/architecture/transactions.md).

- **The shape booleans match upstream's signature.** `Shape.fuse`/`cut`/`common`/`multiFuse`
  take `(other, tolerance=0.0, *, noElementMap)`; the second positional argument is the

  reaches the kernel. Both `test_union` geometry records pass.
