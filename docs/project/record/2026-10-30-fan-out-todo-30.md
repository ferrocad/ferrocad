## What the fan-out settled with evidence

1. **PlanGCS is bindable, and the template objection is wrong.** `GCS` is a namespace and
   `System`, `SubSystem`, `Point`, `Line`, `Constraint` are ordinary classes; the only
   templates are two private members instantiated inside `GCS.cpp`. The dependency set is
   `<Eigen/{QR,Sparse}>`, `<boost/graph/connected_components.hpp>`, `SketcherGlobal.h`,
   `Base/{Tools,Console}.h`, `FCConfig.h` and one FreeCAD-provided Boost shim — **no OCCT**.
   Eleven files, ~13.3k lines, LGPL-2.1-or-later, no build file of its own. ✅ (shape and
   includes; the compile itself is unrun)
2. **The binding is a flat adapter, not an API mirror.** Constraints store `double*` and
   curves are deep-copied, so only indices, tags, scalars and flat buffers should cross the
   boundary. Upstream's own call sequence is `Sketch.cpp:355-433`.
3. **SK1's prerequisite is a sketch-geometry identity, not the lineage layer.**
   `ferrocad_lineage` names shape sub-elements (`ElementRef { shape, name }`); sketches
   store a list of *edges* with no id. Constraints must reference `(object, geometry id,
   PointPos)`; today there is no id to reference.
4. **`Mesh::Feature` exists; only `Mesh::FeaturePython` is missing.** ✅ And a mesh feature
   *owns* a mesh property rather than being one. The persistence caveat matters: `.FCStd`
   drops proxy state, so any SubD cage must live in real properties (`.ferrocad` is the only
   format that keeps the proxy).
5. **Silk is GPL-3.** Curves and CurvedShapes are LGPL-2.1, Nodes LGPL-2.1; SubD's licence
   is unverified (not cloned). A `Sculpt` bundle including Silk is a combined-work
   question, not a packaging detail.
6. **`PartDesign::Body` has no allow-list at all** in this tree — `Group` is an untyped
   `LinkList`. So P3's "declared capability" is not a replacement for an existing list; it
   is the first validation of any kind.
7. **The upstream `Part.Wire(list)` trail is cold**, so the Draft failure needs a
   reproduction before it gets a slice.

## Risks

- **Two creation pipelines for SK4.** Fixing the Rust commit path leaves Draft's
  `make_wire` unclosed and un-undoable; fixing Draft leaves the backlog's claimed route
  untested. Pick one as the acceptance path.
- **`ShapeType` is load-bearing.** Switching to the exact kind is more upstream-faithful but
  will expose places where our booleans return a compound upstream returns as a solid.
- **Licence.** Silk (GPL-3) before any Sculpt work; SubD's licence must be checked at the
  pinned commit.
- **Addon supply chain.** Curves/Silk/SubD are external, unpinned, and carry native Python
  dependencies; vendoring is mandatory because the upstream checkout is sparse and offline.
- **Stubs that satisfy tests.** A TechDraw page stub and a `makeWireString` stub can make a
  test pass while the feature produces nothing; mark them won't-do explicitly rather than
  silent.
