### 0.1 What the tree already has

- **The OCCT boundary is Rust.** `ferrocad_part_cxx` is gone; `ShapeFix`, `ChFi2d`,
  topology, boolean history and the curve/geom2d helpers are Rust over
  `ferrocad_occt_cxx`'s sys bindings. The C++ that remains is the published sys crate,
  not our seam.
- **One document, four runtimes.** `RustAppBackend` is the document half of every desktop
  and browser configuration; `PythonScriptHost`, `PywasmScriptHost`, `JsScriptHost` and
  `runtime=plain` are the script halves. `ferrocad_shell_web` switches them in the
  browser; the desktop switches with `--script-host=`.
- **The browser shell is real.** M0–M6: the shell runs in Chrome, draws a `Part::Box` +
  `Part::Fillet` document on the wasm kernel, edits it, opens/saves `.FCStd`, and passes a
  headless smoke check.
- **Mods are a delivery format.** Packs carry entry scripts and the `Resources/` they read;
  wasm addons use the `ferrocad_addon` ABI; the browser and desktop compose the same
  ordered host chain.
- **The interaction work landed.** Transform A1–A3 and U1–U6: one `TransformSession`, the
  Move pill, the 3-D tape, loadout slots, `Select ▾`, hover-to-arm, and the locked pending
  context.
- **The manipulators are editors.** Push/Pull and Fillet share one pending-edit writer, a
  docked numeric row, a stem that rides the swept ghost, a hard range whose ceiling the
  kernel measures by bisection, and re-opening: picking the cap of an extrusion or the
  round (face or boundary edge) of a fillet seeds the handle and edits that feature in one
  transaction. A feature the kernel refuses is rolled back, and a refused commit re-arms
  the handle. See §20 of
  [`../developer/interaction/gizmo-manipulators.md`](../../developer/interaction/gizmo-manipulators.md).
- **The Part containers are upstream-shaped.** `Refine` is read (default on, unified by the
  kernel and re-named through a measured history), `MultiCommon.Behavior` exists, a lone
  compound argument is flattened the way upstream flattens it, and the four
  `Part_Fuse`/`Cut`/`Common`/`Compound` commands create one undoable object over the
  selection. See
  [`../developer/workbenches/part-containers.md`](../../developer/workbenches/part-containers.md).
- **SimpleCAD's name surface is complete** (all 42 `Part.*` names resolve; `makeWireString`
  is on the Rust text stack), and the S4.1–S4.6 façade is in the tree (view facade, ranked
  pick, `SelectionObject`, workplane/face frames, push/pull stem, preview decision).
- **The Sketcher is still a geometry container.** No `Constraints` property and no solver;
  PlanGCS remains vendored upstream and bindable, but SK1 has not started.

**Round 1 — the boolean gap is closed (2026-11-14).** The six container objects now read

`MultiFuse` arity, pass the fuzzy value through, and have their four commands. Measured on
the current tree; the contract is
[`../developer/workbenches/part-containers.md`](../../developer/workbenches/part-containers.md).

- [x] **`Refine` is real.** Declared, read in `Boolean::execute` and `Multi::execute`, and
      defaulted to upstream's preference value (`true`, `FeaturePartBoolean.cpp:63`). The
      kernel's unifier runs after the operation and its lineage is folded onto the
      operation's; because the unifier rebuilds every sub-shape it keeps, the relations are
      measured (area + centre of mass, edge length + midpoint, vertex point) rather than
      `IsSame`. Two bodies fused face to face report **6** faces with `Refine` on and **10**
      with it off. Part conformance stays **531/0/0/12** with the default flipped.
- [x] **`MultiCommon.Behavior`.** `{"CommonOfAllShapes", "CommonOfFirstAndRest"}`, group
      `Compatibility`, hidden, default `CommonOfAllShapes` — and it decides whether a lone
      compound is expanded (500 mm³ intersection) or kept whole (2000 mm³ compound).
- [x] **Single-compound flattening.** `MultiFuse` and `MultiCommon` expand a lone compound
      into its direct children, repeatedly, through the new
      `GeometryBackend::children`/`shape_type`; a compound among several arguments is left
      alone.
- [x] **`MultiFuse` arity.** Fewer than two shapes after flattening is upstream's
      `"Not enough shape objects linked"`; `MultiCommon` accepts one.
- [x] **`Part.generalFuse(fuzzy_value)`** reaches the kernel (`BRepAlgoAPI_BuilderAlgo::SetFuzzyValue`).
- [x] **The interactive commands.** `Part_Fuse`, `Part_Cut`, `Part_Common` and
      `Part_Compound` in the parametric edition: upstream's selection rules, one transaction,
      the operand's appearance copied, the operands hidden behind a boolean, a compound that
      leaves its links visible. `tests/test_part_booleans.py` pins all of it.
- [ ] **`Part::PropertyShapeHistory` — deliberately not implemented.** Upstream stores a

- [ ] **Tree nesting.** A `Part::Compound`/`MultiFuse` is one tree row; upstream's
      `getSubObjects` nesting of the operands is not implemented.
- [ ] **PartDesign's boolean features** (`PartDesign::Boolean`) and `Part::Section`.
- [ ] **Draft remainder.** `Import.readDXF` (no `Import` package; size an ASCII subset or

## P4 — Constraints and sketches, with a bound solver

**Scope decision unchanged: FerroCAD owns everything around the solver and does not write
one by default.** The constraint model, storage, selectors, diagnostics and UX are ours;
the numerical solve comes from PlanGCS (2D) or OndselSolver (3D).

### 4.1 State

- PlanGCS is vendored upstream, **not templated**, dependency-light (Eigen, one Boost
  graph header, FreeCAD stubs) and **verified bindable** in the 2026-10-30 fan-out.
- OndselSolver is still not checked out; it is unverified for sketch constraints.
- No constraint model, no `Constraints` property, no solver in the workspace.
- **SK1's prerequisite is still missing:** sketch geometry has no stable id, so a
  constraint cannot reference a curve across a recompute.

### 4.2 Slices

1. **SK1 — the geometry identity and the constraint model.** Add a document-scope geometry
   id (UUID + curve parameters) to each sketch entry, then typed constraints holding
   `(object, geometry id, PointPos)` + kind + params. *Acceptance:* round-trips through
   `.FCStd`, resolves after a reordering recompute, reports a dangling reference.
2. **SK2 — the solver adapter.** One trait over the chosen solver, with DOF analysis,
   redundant/conflicting detection and deterministic reporting mapped back to constraint
   ids. *Acceptance:* a triangle with three dimensions converges from a perturbed start;
   an over-constrained sketch returns the redundant set; results are identical across runs.
3. **SK3 — `Sketcher::SketchObject` becomes real.** Add `Constraints` and a solve result;
   add `python/Sketcher` (`addConstraint`, `delConstraint`, `setDatum`, `solve`,
   `getDatum`). *Acceptance:* an upstream-shaped script builds a constrained sketch and
   reads back its DOF count. This also unblocks P2's `make_sketch`.
4. **SK4 — draw on a workplane.** *(a)* close the loop in `PolylineTool`; *(b)* register the
   tool in the parametric edition and add a `create` provider that builds one
   `Part::Feature` inside one named transaction; *(c)* the acceptance test: four snapped
   clicks on a tilted plane, every vertex within f32 tolerance, one undo removes it. The
   ordering, snapping and routing are built; the creation half does not exist. Decide the
   two-creation-pipelines question and project tool points onto the active plane.
5. **SK5 — path to solid.** Extrude the committed wire through `Part::Extrusion` in one
   transaction; editing the path updates the extrusion.
6. **SK6 — constraints as refinement.** Select geometry, add a dimension, watch the profile
   and its extrusion update; an unconstrained drag still works.

Decisions still open: the state channel for "solved / failed / over-constrained"; whether an
attached sketch re-maps when its support's lineage changes; and whether OndselSolver is ever
needed for assembly. The 2D-crate and one-model decisions are settled (one kernel-free model
crate + one solver binding).

## Closed since the last backlog

The 2026-11-13 backlog closed with two red gates fixed; this rotation was the manipulator
round. In order:

- **The manipulator became a numeric editor.** One pending-edit writer for a drag and a
  typed value, a docked row that mirrors a drag into unfocused fields, `Tab`/`Enter`/`Esc`,
  and a zero distance that is "no edit".
- **The handle rides the ghost.** The stem's base is the swept face's centroid, so it
  stays under the pointer; `set_anchor` moves the sweep origin; `update` keys on the ghost
  anchor.
- **The range is the kernel's.** The stage proves a floor and nothing more (the geometric
  "half the thinnest extent" ceiling was wrong and was removed); `ferrocad_parametric`
  bisects a real `makeFillet`, cached per arming and cleared on any document edit.
- **Existing operations became editable.** A cap or a round seeds the handle and the
  commit edits that feature in one transaction; a sign flip swaps the boolean without
  stacking, and a fillet's round *edge* is the same handle as its face.
- **Failures no longer break the body or the handle.** An `Invalid` feature is rolled back
  before it is committed, and a refused commit re-arms the manipulator instead of leaving a
  ghost with no `✗`/`✓`.
- **The Part layer stopped dropping provenance.** Dress-up features store the kernel
  history, partial maps are completed with identity relations, and a map entry of a
  different kind falls back to the shape's own naming rather than handing the kernel a
  face for an edge.
- **The startup sample became a real asset.** Regenerated with the kernel's provenance,
  tracked, and verified identical in tree, properties and mesh; the `.FCStd` lineage
  sidecar now survives a save/reopen.
- **The contract gate is honest again**: the two startup-document tests read the document
  name the host reports, and the extension-set contract re-pins at 49 modules.

The evidence is in [`2026-11-13-november-round.md`](2026-11-13-november-round.md)
