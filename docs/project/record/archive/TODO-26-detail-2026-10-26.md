### 0.1 What the 2026-10-25/26 round changed — and what it did not

The interactive layer landed; the geometry/OCCT tail did not move.

- **Wheel, form and deferred drag.** `ferrocad_widgets::wheel` is a sidecar radial
  widget with tap-to-latch and drag-to-flick; `Shell` resolves a read-only context
  target, opens the wheel from `Space` or a right click, and promotes the target only on
  commit. The `Move` form is a floating dielectric HUD with no backdrop; a deferred
  gizmo drag mirrors its delta into `dx/dy/dz` and typing previews immediately. The HUD
  clamps into the viewport, freezes while focused, and closes when the selection changes.
- **Gizmos.** The triad hugs the object's own origin (the anchor decision is recorded in
  `transform-ux.md`); mode is sticky session state (`Translate` / `Rotate` /
  `Universal`), `App_Rotate` is a wheel and keyboard verb, and a header `Gizmo` control
  exposes configuration. The height grip was separated from the toy workbench.
- **Settings and dev tools.** A settings card is a tool, not a selection-bound surface.
  Colours get a swatch/palette, bounded numbers a slider, quantities a unit-aware
  scrub/dial, booleans a toggle and enums a select box. Dev tools gained a scrollbar, a
  multi-open accordion, a status-bar bug button and a floating always-on-top window.
  Edition appearance presets and a reset expose per-edition ink and geometry defaults;
  the precedence model is documented.
- **Gizmo accessibility and rendering.** The style now has an outline halo, a hover
  width cue, a floored 24 px grab radius, a `ghost_alpha` ceiling and 5° rotation
  detents. The workbench manipulators (toy height grip, Part dress-up arc) use the same
  style. The triad is an `Always` overlay with no ghost pass, so an origin-inside-the-
  body gizmo no longer renders as a 20 % watermark. Ribbons carry a lateral UV and use
  the new unlit `fs_ribbon` stage (`fwidth`/`smoothstep`), arrowheads are filled
  triangles, planes draw an L-corner rim, and a hovered plane closes the full casing.
  Edge-on axes/planes fade out and leave the hit test.
- **Platform and release.** `opencascade-sys` takes upstream PR #234; the MSVC bridge
  compiles, the Windows edition leg is back, and the Parametric artifact bundles its
  OCCT closure. The `bite-gp-*` family is pinned to 1.24.402 (with the Windows
  `gpu-allocator` pin). 0.1.3 and 0.1.4 were cut.
- **Docs and CI.** The generated API pages are regenerated and checked; the Linux
  desktop dependencies come from the shared composite action; `typing_extensions` is
  installed only where the upstream tree needs it. The book publishes from the separate
  [`ferrocad/docs`](https://github.com/ferrocad/docs) repository, with clean paths and a
  working 404 base; the reference landing page is `index`, not `README`.

What it did **not** do:

- The `curve_of` kinds still report `unsupported` (the thread solid landed in the
  2026-10-26 fan-out, §0.2).
- SimpleCAD S1 has not been run against a Part-linked image.
- macOS packaging/signing is still unbuilt (the dead `cocoa` import is patched).
- Re-pivot, push/pull and the thread solid landed after this summary was written;
  see §0.2. Select mode (slice 4) is still open.
- Rotate rings are drawn and cased, but their brush/arc interaction and edge-on hit
  policy are open.
- Tab/digit escalation from an armed gizmo into the Move form is planned, not built.

### 0.2 What the 2026-10-26 fan-out round changed

Four tracks ran in parallel and landed together:

- **Re-pivot (P3 slice 3).** `GizmoTarget::Origin` is a 10 px disc appended after the
  handles (every pick id unchanged; priority **origin > axis > plane > ring**).
  Dragging it moves the real frame and snaps through the viewport's existing
  candidates (vertex, edge mid, face centre, workplane origin, then the body point,
  then the grid). Release emits `ViewportEvent::GizmoOrigin { point, kind }`; the
  shell keeps a session `user_origin` (not undoable, not a document property), a new
  selection or a wheel promotion clears it, `Esc` restores the object origin, and the
  handle is disabled while the translation HUD is open.
- **Push/pull stem (P3 slice 5).** `ferrocad_part_gui::push_pull` derives a planar
  face's centroid and outward normal from the item's own tessellation, draws an amber
  normal stem (reusing the triad's axis solver and linear readout), and commits
  `push_pull` + `extrude`/`pocket` with the face element and the signed distance. The
  parametric script builds `Part::Extrusion` and one `Part::Fuse`/`Part::Cut` in a
  single transaction, hides the intermediate prism, and re-derives the normal in the
  shape-local frame. Non-planar faces get no stem; the solid appears on release.
- **Thread through-sections (P1).** `Part.makeThread` is upstream's two-profile solid:
  two 2D ellipse+chord wires on coaxial cylinders (`radius`, `radius + depth`),
  lofted with `BRepOffsetAPI_ThruSections`. The exact vertices lie on the two
  cylinders; `(pitch, depth, height, radius) = (1, 0.5, 4, 2)` measures one shell,
  volume **7.436**, and a positive tessellation.
- **SimpleCAD S1.** The harness ran all 88 modules on the bare `python/` image:
  **165 passed, 0 failed, 1 errored, 1 skipped, 0 harness exceptions**; 71 modules
  did not load (`Part` 61, `Mesh` 10). The baseline is recorded in
  [`workbenches/simplecad-bringup.md`](../../research/simplecad-bringup.md) §7. It is a
  load-boundary measurement, not a Part baseline.
