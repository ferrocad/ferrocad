# D0 — import the headless Draft core

Status: task (2026-10-22). Backlog entry **P1** in
[`TODO-22-10-2026.md`](../TODO-22-10-2026.md). Companion to
[`qt-strategy.md`](../workbenches/qt-strategy.md) §2.6 and the measurements in
[`TODO-21-10-2026.md`](../record/TODO-21-10-2026.md) §3.

## Goal

Make the **Qt-free half of upstream Draft import and run headless** against the
FerroCAD facade, and make that a measured baseline: a `--draft` group in
`tools/conformance.py` that reports load errors by missing name.

The probe showed 14 of 17 representative modules already import with five small fixes
applied in-process. D0 lands those fixes for real and adds the harness group. D0 does
**not** make `Draft` itself importable: `Draft.py`, `SVGPath` and
`draftfunctions.offset` still need `import Part`, which is the `Part` kernel slice.

## What D0 is not

- Not the `Part` kernel (edges/wires/faces). That is the next slice and is tracked in
  `TODO-22-10-2026.md` P1.
- Not the Draft GUI (`InitGui`): it needs the Qt split plane and `FreeCADGui`
  interaction services.
- Not every Draft module: `draftmake.make_circle`, `make_arc_3points` and
  `draftobjects.shapestring` import `Part` at module scope by design.

## Subtasks

### D0.1 — `Quantity(value, Unit)`

`crates/ferrocad_py/src/lib.rs:483`: the 2-arg branch extracts the unit as a `String`
only. Draft calls `App.Units.Quantity(100.0, App.Units.Length)` at import time.

- Accept a `PyUnit` (and keep `str`) in the second position; build the same
  `Quantity::new(value, unit)`.
- Test: `Quantity(100, Units.Length) == Quantity(100, "mm")`, and a `Quantity`
  passed as the second argument still raises the same `TypeError`.

### D0.2 — vendored `lazy_loader`

Draft uses `import lazy_loader.lazy_loader as lz` and
`lz.LazyLoader("Part", globals(), "Part")` in 25 files (10+ modules on the import path).

- Add `python/lazy_loader/` with `LazyLoader` (import on first attribute access and
  replace the module global) and an `__init__` that re-exports it. Keep it dependency
  free.
- Test: a module that raises on import is not imported until the attribute is read;
  the second read returns the cached module.

### D0.3 — `PySide` compatibility alias

Upstream imports `PySide` (Qt5-style); the system ships **PySide6 6.10.2**. Draft's
import-time use is `QtCore` (`QT_TRANSLATE_NOOP`, `QCoreApplication.translate`,
`QLocale`) and `QtWidgets` for the widget classes; the GUI itself is out of scope.

- Add `python/PySide/__init__.py` that aliases `PySide6.QtCore/QtGui/QtWidgets` (and
  `QtSvg` *if present*) into `sys.modules` as `PySide.*`, with `QT_TRANSLATE_NOOP` at
  the package level.
- Guard missing modules (`QtSvg` is absent); a missing module must not break the
  import of `QtCore`.
- Test: `from PySide import QtCore, QtWidgets`; `QtCore.QT_TRANSLATE_NOOP("c", "s")`;
  `PySide6` is not imported twice; `QtSvg` absence is tolerated.

### D0.4 — `Draft_rc` resource stub

`draftutils/utils.py` and `Draft.py` do `import Draft_rc` when `GuiUp`; the module is
generated by `pyside-rcc` upstream. It is only a resource bundle plus `__name__`.

- Generate a minimal `Draft_rc` in the mod fetcher (`xtask mods`) or provide a tiny
  module beside the Draft mod with `qInitResources()` as a no-op.
- Test: `import Draft_rc` succeeds and `Draft_rc.__name__` is truthy.

### D0.5 — `src/Ext/freecad` on `sys.path`

`DraftVecUtils` does `from freecad.deprecation import deprecated`; the package lives in
`src/Ext/freecad` and its `__init__.py` is generated from a template.

- Add `src/Ext/freecad` to the sparse checkout and put its parent on `sys.path` from
  the boot (or copy the package into the Draft mod directory and ship it).
- `deprecation.py` needs `typing_extensions`, which is present; verify before relying
  on it.
- Test: `from freecad.deprecation import deprecated` with the upstream tree on the
  path, and without it (a clear error).

### D0.6 — the `--draft` conformance group

`tools/conformance.py` has `DEFAULT_FILES` (App) and `PART_FILES` (`--part`). Add a
`DRAFT_FILES` group and `--draft`:

```python
DRAFT_FILES = ["test_base", "test_grid_settings", "test_pivy",
               "test_airfoildat", "test_import"]
```

(`test_import_tools` imports `draftguitools`, so it is GUI-adjacent and excluded.)

- Acceptance: each file imports and runs; report pass/fail/error/skip and load errors
  naming the missing symbol. The group is a **measurement**, not a gate, like
  `--part`.
- Run it from the repo root with `PYTHONPATH=python` and
  `../freecad-upstream/src/Mod/Draft` + `../freecad-upstream/src/Ext` on the path.
- Record the upstream revision in the report.

## Acceptance

- With `GuiUp == 0`, `from draftutils import params` succeeds and
  `params.get_param("textheight")` returns a value (the preference `.ui` parse, see
  the Qt note) — or the group records the exact remaining failure if the Qt resource
  reader is required.
- `import draftobjects.rectangle` succeeds.
- The 14 modules in the probe table import (TODO-21 §3).
- `python3 tools/conformance.py --root ../freecad-upstream --draft` prints a summary
  with **no load errors** for `test_base`, `test_grid_settings`, `test_pivy`,
  `test_airfoildat`, `test_import`; `test_import` may fail at runtime on `Part`.
- `cargo test -p ferrocad_py` and the Python facade suite stay green.
- The fixes are covered by tests, not just by the probe.

## Risks and notes

- **`textheight`/`constructioncolor`** are declared only in
  `Resources/ui/preferences-*.ui` and reach `PARAM_DICT` by parsing them through
  `QtCore.QFile`. If D0 does not add a Qt resource reader, `DraftGui` fails later; the
  D0 group must not depend on those keys. A pure-Python `.ui` parser in the `PySide`
  shim (or a `QFile` that serves the mod's `Resources/ui`) is the cheapest fix; decide
  in D0.3.
- **Upstream is a moving target.** Pin `33adf61` for the baseline; record the revision
  with every number.
- **PySide6 vs PySide5-isms.** `QAction` is in `QtGui` in Qt6; `QtCore.SIGNAL` does not
  exist. Draft's import-time surface is small, but a later GUI slice will meet them.
- **No compatibility with upstream FreeCAD is required** for this work; the target is
  the FerroCAD facade.
