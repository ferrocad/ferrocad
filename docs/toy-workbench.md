# The toy workbench: the generic interaction model, without a kernel

Status: reference (2026-10-20). Companion to
[`architecture.md`](architecture.md) §10, [`gizmo-manipulators.md`](gizmo-manipulators.md)
and [`repackaging.md`](repackaging.md).

## Why it exists

The interaction registry makes a strong claim: **a workbench contributes its own
manipulator, and the shell, viewport and stage never name a workbench.** Part proves
that claim, but Part also brings OCCT, a tessellator, a feature graph and a Python
module — so a failure does not say *which* layer broke, and the test cannot run in the
fast CI job.

`ferrocad_toy` is the smallest edition that still tells the truth. It links **no
geometry module at all**:

| Piece | Part edition | Toy edition |
| --- | --- | --- |
| Document object | `Part::Feature` (`Shape`) | `App::FeaturePython` (`Height`, a `PropertyLength`) |
| Display mesh | `Part.Shape.mesh()` (OCCT) | a cube generated by the app script |
| Manipulator | `DressUpScrubber` over an `EdgeN` | `HeightGrip` over the whole object |
| Manifest | `interaction` → `Part::Fillet`/`Chamfer` | `interaction` → `Height = …` |
| Kernel | OCCT | none |

If the toy's loop works, the seam is generic. If only Part's works, something
Part-shaped leaked into the shared layers.

## The loop it exercises

```text
document ── stage_meshes ──▶ DisplaySync::build ──▶ Stage (entity → object map)
   │                                                  │
   │                                     click: SelectionRef::whole(entity)
   │                                                  ▼
   │                                    Contributions::manipulator_for
   │                                                  │
   │                                       Box<dyn Manipulator> (HeightGrip)
   │                                                  │ drag
   │                                                  ▼
   │                                        InteractionCommit
   │                              { manipulator: "toy_height", action: "set",
   │                                values: [h], readout: "H 24.33 mm" }
   │                                                  │
   │                       display.object_of(target) ─┘
   ▼                                                  ▼
app script ◀──── ferrocad_shell.interaction ──── python::apply_interaction
   │  FreeCAD.interaction(obj, "toy_height", "set", "", [h])
   ▼
Height property ── recompute ──▶ stage_meshes ──▶ rebuilt stage
```

Every arrow is the same code the Part edition uses. Only the two endpoints differ.

## The pieces

| Path | What |
| --- | --- |
| `crates/ferrocad_toy/src/lib.rs` | `HeightGrip` (implements `ferrocad_stage::Manipulator`), the `height_grip` factory (whole-object selections only), and 6 unit tests |
| `crates/ferrocad_toy/src/main.rs` | the edition binary: `run_edition_with(…, Contributions::with_manipulator(height_grip))` |
| `python/ferrocad_toy/__init__.py` | the app script: the cube mesh from `Height`, the `toy_height` interaction provider, and a demo slab |
| `crates/ferrocad_toy/tests/round_trip.rs` | the end-to-end test: selection → factory → drag → commit → property → re-sync |
| `crates/ferrocad_parametric/tests/manipulator_round_trip.rs` | the same loop with the **real** Part arc and a `Part::Fillet` |

Run it:

```sh
cargo run -p ferrocad_toy        # a window; click the slab, drag the grip
cargo test -p ferrocad_toy       # the kernel-free end-to-end test
```

## What it proves, precisely

- **The factory rule is the workbench's.** Part claims `EdgeN`; the toy claims whole
  objects. `Contributions` does not care.
- **The commit is neutral.** The shell never sees `DressUpValue` or a height; it sees
  `InteractionCommit` and hands it to the app script by id.
- **The document side is Python.** The toy writes a property; Part creates a feature.
  Neither is known to `ferrocad_gpui`.
- **Re-sync is generic.** `DisplaySync` rebuilds the stage and the entity map from
  whatever `stage_meshes` returns.
- **The base app links nothing.** `ferrocad` (the general edition) registers no
  factory and no provider, so `stage_meshes` is empty and the sample scene stays.

## Non-goals

The toy is not a workbench: it has no persistence, no feature graph, no selection
semantics beyond "whole object", and no kernel. It is a reference implementation of
the extension point and a test fixture. When the extension point changes, it is the
first thing to update — if it breaks, the change was not generic.
