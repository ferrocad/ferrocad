# User documentation

FerroCAD has two kinds of user: **UI users**, who work in the application window,
and **API users**, who work through the Python console, a macro or a script. They
share the same document model; the API is the contract and the window is one client
of it. The gentle introduction is
[UI users and API users](explanation/ui-and-api.md).

## Two readers

- **UI users** — the window is the guide. The generated pages below are not
  click-throughs; the [repository README](../../README.md) shows the window.
- **API users** — the pages below are your examples. They run the same `FreeCAD`
  calls as a console line, a macro or a script, with no window at all.

The pages are generated by running an ordinary Python script against the real
`FreeCAD` facade: the code blocks are the code that executed and the tables are the
values it read back. They are grouped the way Diátaxis groups them: a **tutorial**
teaches by doing, a **how-to guide** answers one task, the **reference** lists what
exists, and an **explanation** page says why. Reference is the generated
[Python API reference](../python-api/index.md); the addon contract is
[`mods/`](../mods/README.md). A workflow that is not implemented has no script, so
it has no page — this index is the progress list, not a backlog.

- [Model a NURBS surface](how-to/model-a-nurbs-surface.md) — `Part.BSplineSurface` is the surface counterpart of `Part.BSplineCurve`. It holds the whole control-point description — poles, weights, knot vectors with multiplicities, and the two degrees — and turns it into a face with `toShape()`.
- [Make a solid from a NURBS surface](how-to/solid-from-a-nurbs-surface.md) — `Part.BSplineSurface.toShape()` returns a **face** — a surface with a boundary. A solid needs a closed shell. There are two common ways to get there: extrude the face, or cap its open ends and sew the pieces into a shell.
- [Make 3-D text from a font](how-to/text-to-3d.md) — `Draft.make_shape_string` turns a string and a font file into a flat, single-line **compound of faces**; the `Part` workbench extrudes those faces into letters and fuses them onto — or cuts them out of — a plate. This is upstream's Draft ShapeString in its scripted form, and it is the starting point for 3-D text.

## Regenerating and capturing

```sh
python3 tools/userdocs.py                # refresh every page
python3 tools/userdocs.py --check        # non-zero exit if a page or image is stale
python3 tools/userdocs.py --capture      # re-render the images (needs a GPU adapter)
python3 tools/userdocs.py --write-manifest  # adopt existing PNGs without a GPU
python3 tools/build_book.py              # assemble the mdBook edition
```

The check is the part that matters: it is cheap, needs no GPU, and it is what
keeps the pages honest in review and in CI. The mdBook edition is assembled from
these pages, so it inherits the same guarantee.

## Screenshots and their limits

The screenshots are real viewport pixels, captured by
`python3 tools/userdocs.py --capture` from the render specs the workflows record
and stored under `docs/user/images/`. Capturing needs a GPU adapter; the pages and
the `--check` gate only read the committed PNGs, so CI stays cheap and GPU-free.
On a machine with no adapter the capture says so and leaves the images untouched.

`docs/user/images/manifest.json` pins each generated image to its render spec and
its PNG bytes. `--check` compares both, so a changed camera or shape fails review
even without a GPU. A page may also use a hand-supplied illustration (no render
spec); those are deliberately absent from the manifest. For a one-off viewport
image outside the page pipeline, use `tools/screenshot.py`; its `--mode chrome`
captures the app window (title bar, header controls, Dev Tools) and `--mode desktop`
captures the display. See
[`../developer/workbenches/screenshot-tool.md`](../developer/workbenches/screenshot-tool.md) for the three
scopes and when to use each.

What the pages are **not** is a claim of upstream parity. Only what runs here is
documented here; the gap is measured by
[`../developer/workbenches/conformance.md`](../developer/workbenches/conformance.md).
